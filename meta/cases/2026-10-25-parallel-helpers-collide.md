# 사례: 동시에 도는 도우미끼리 같은 자리를 써서 부딪힘(글로 된 규칙, 지휘가 판단)

종류: 여러 도우미가 같은 저장소·컴퓨터에서 동시에 일할 때, 겹침을 막는 규칙이 글로만 있고 지휘 세션의 판단에 맡겨져 있어, 바쁠 때 겹친 채로 띄워지거나 낡은 바탕에서 끝난다.

앞선 사례 [shared-checkout](2026-10-25-shared-checkout.md)(같은 작업 폴더·차례 번호·공유 목록)는 장치(작업 폴더 훅, 시각 이름, 일마다 파일 하나)로 막았고 그날 다시 나지 않았다. 아래 넷은 그 장치가 덮지 않은 자리에서 같은 모양으로 났다.

**사례 1: 같은 소스 파일을 두 도우미에게** (marketing-with-ai, 2026-10-25 밤)
- 입력: 두 도우미(상품 블록 초안, 고르기 목록 서버 검색)가 같은 화면 파일의 같은 설정 부분을 고쳤다. 일 목록에 "겹침 위험(고치는 곳)" 칸이 있었지만 도는 가지와 견주는 것이 없었고, 그때그때 띄운 도우미는 목록에 없었다.
- 결과: 합칠 때 충돌.
- 맞는 결과: 띄우는 순간 고칠 곳이 살아 있는 가지의 변경·맡김과 겹치면 막힌다.

**사례 2: 낡은 바탕에서 끝남** (같은 날)
- 입력: 도우미들이 사용 한도로 몇 시간 멈춘 사이 바탕이 움직였다. CPU를 아끼려 "바탕을 다시 합치지 말라"고 지시했다.
- 결과: 한 도우미의 e2e가 바탕에서 지운 버튼을 찾았다. 의미 충돌이 맥락 없는 지휘의 합치기 때 드러났다.
- 맞는 결과: 도우미가 보고 직전에 바탕을 한 번 합치고 닿는 시험을 다시 돌린다.

**사례 3: 세션 scratchpad를 같이 씀** (같은 날)
- 입력: 도우미들이 세션 하나의 scratchpad를 같이 쓴다. 두 도우미가 같은 이름(`msg1.txt`)으로 커밋 메시지를 썼다.
- 결과: 한 도우미의 메시지를 다른 도우미가 덮어써 틀린 커밋 메시지가 들어갔다.
- 맞는 결과: 도우미마다 자기 칸(`scratchpad/<일>/`)에만 쓴다.

**사례 4: 컴퓨터 용량** (같은 날, [unread-orchestration](2026-10-25-unread-orchestration.md) 사례 2와 같은 원칙)
- 입력: 도우미 4~6개가 각자 전체 검사·e2e·타입 검사와 Chrome을 동시에 돌렸다. 원칙 4(좁은 자원에 용량만큼만)는 글이고, 띄울 때 점검으로 보이기만 했다.
- 결과: 12코어에 부하 138, e2e 128개 중 15개 시간 초과(거짓 실패), 단위 시험 5초 시간 초과.
- 맞는 결과: 무거운 명령은 컴퓨터 전체에서 자리 수만큼만 돈다.

진단: 1(규칙이 있었는데 글이라 안 지켜짐 — docs/agents.md 원칙 4·8, 일 목록의 겹침 칸). 사례 3은 규칙이 없던 자리지만 shared-checkout과 같은 구조(여럿이 쓰는 자리에 동시에 씀)의 두 번째 사례라 같은 원칙(원칙 10)을 넓혀 덮는다. 규칙 글은 더하지 않고 장치를 둔다: 띄울 때 겹침 검사(`work-guard.py launch`), 보고 전 바탕 검사(`handback`), scratchpad 칸 검사(`scratch`), 무거운 명령 자리(`scripts/heavy/slot.sh`). 뿌리 연결: P2(같은 실수가 두 번이면 글보다 높은 장치로). P1: 검사는 1초 안(도우미 49개 작업 폴더에서 0.5초)이고, 사람이 돌리는 절차가 아니다.

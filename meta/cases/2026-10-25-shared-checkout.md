# 사례: 여러 세션이 한 자리·한 숫자를 잠금 없이 같이 씀

종류: 동시에 일하는 쪽이 둘 이상인데, 일할 자리(작업 폴더·가지)와 이름 붙이는 숫자를 함께 쓴다.

**사례 1** (marketing-with-ai, 2026-10-25)
- 입력: 두 Claude 세션(합치기 대장, 마스터보드)이 저장소 폴더 하나와 가지 하나(merge/b6)에서 번갈아 커밋했다. 결정 기록 번호는 "가장 큰 번호 + 1"로 매긴다.
- 결과: ADR 0013이 두 장 생겨 결정 기록 시험이 실패했다.
- 맞는 결과: 동시에 만들어도 이름이 겹치지 않는다(마이그레이션처럼 시각으로 짓는다).

**사례 2** (같은 날)
- 입력: 개발 기록도 같은 파일 끝에 "E번호 + 1"로 덧붙인다.
- 결과: E95, E96, E98이 두 번씩 쓰였다.
- 맞는 결과: 사건 하나 = 파일 하나, 번호 없이.

**사례 3** (같은 날)
- 입력: 기록 훅은 파일의 표시 하나 뒤 커밋을 모두 "기록할 것"으로 본다.
- 결과: 한 세션의 훅이 다른 세션의 합침 커밋을 기록하라고 멈춰 세워, 그 세션이 남의 일을 대신 기록했다.
- 맞는 결과: 훅은 지금 가지가 갈라진 뒤의 커밋만 본다.

**사례 4** (같은 날)
- 입력: CONTRIBUTING 5절은 "커밋 직전에 `git diff --cached --stat`로 남의 파일이 딸려 오지 않았는지 본다"고 글로 정한다.
- 결과: 합치는 세션이 바쁜 중에 `git add -A`를 썼다. 남의 파일이 섞일 수 있었다(대조해 보니 이번엔 없었다).
- 맞는 결과: 세션마다 자기 작업 폴더라 섞일 남의 파일이 처음부터 없다.

처음 대응(작업 목록 파일 + "시작 전에 본다" 규칙)은 글로 막고, git에 있는 사실을 베끼고, 공유 숫자를 다른 파일로 옮긴 봉합이었다(P1, P2, P3 위반). 사용자가 "근본 원인과 미연에 막는 체계"를 물어 다시 진단했다.

진단: 1(5절 규칙이 있었는데 글이라 안 지켜짐) + 2(번호 매기기 규칙이 동시 작업에서 틀림). 뿌리 연결: P2(글보다 높은 장치), P3(누가 어디서 일하나는 git이 원본).

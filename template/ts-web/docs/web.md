# 웹 서비스 규칙 (TypeScript + SQL DB)

화면이 있고, TypeScript로 짜고, SQL DB(Postgres)를 쓰는 프로젝트에 더하는 규칙이다. 일반 규칙은 [CONTRIBUTING.md](../CONTRIBUTING.md)와 [code-rules.md](code-rules.md), 도구 선택은 [stack.md](stack.md)가 맡는다.

## 1. 화면·문구는 샘플 먼저

바뀌는 부분을 가짜 데이터로 그린, 눌러 볼 수 있는 HTML 한 장으로 피드백을 모은다. `visual-explain` 스킬(있으면)이나 Artifact로 만든다.

- "지금"과 "바뀐 안"을 나란히 둔다. 바뀐 구획은 실제 폭으로 그린다.
- 색·글자는 디자인 값 문서(`DESIGN.md`)의 이름 있는 값으로만 쓴다.
- 펼침·탭 전환 같은 동작은 스크립트 몇 줄로 살린다. 저장·서버 호출은 만들지 않는다.
- 정할 것은 채팅으로 묻지 않고 샘플 안의 결정 상자로 둔다. 안은 둘~셋, 권장안 제목에 "(권장)".
- 확정 신호는 "확정"·"이대로 해"·"끝" 같은 말이다. "좋네"·"여기만 하나 더"는 아니다. 애매하면 한 문장만 묻는다.
- 화면과 서버가 섞이면 화면을 샘플로 확정한 뒤 서버를 만든다.

| W2 | 처음 쓰는 사람이 막힐 곳이 생기나? 빈 상태·안내·오류 문구는? |

## 3. 타입 (TypeScript)

- `strict`를 켠다. 서버·화면 모두 타입 검사를 받는다.
- 타입은 DB에서 만든다(stack.md). 같은 모양을 손으로 다시 적지 않는다.
- switch는 `default`에서 `` `${x satisfies never}` ``로 모든 경우를 처리했는지 검사한다.
- 종류마다 칸이 다르면 `kind`로 가르는 판별 유니온을 쓴다.
- `as`는 좁히기(판별 칸 → `in` → 타입 가드)로 바꾸고, 남기면 앞에 `// SAFETY:`를 단다.
- `enum` 대신 문자열 유니온·`as const`를 쓴다. 빌드 없이 실행하려면 지울 수 있는 TS 문법만 쓴다.
- 입구의 바깥 값과 환경 변수는 Zod 스키마 하나로 검사한다. 환경 변수 검사에 실패하면 부팅을 멈춘다.
- 규칙 파일은 실패를 `{ ok: false, reason }`처럼 값으로 돌려준다. 예상 못 한 것만 throw하고, 오류 처리 한 곳이 기록한다.

## 4. SQL DB (Postgres)

- 상태 값은 문자열 하나 + `CHECK`로 둔다.
- 되돌릴 수 없는 외부 호출의 장부 줄은 유일 키 + `INSERT … ON CONFLICT DO NOTHING`으로 먼저 잡는다.
- 마이그레이션 파일 이름은 만든 시각 `YYYYMMDDHHMMSS_설명.sql`(UTC)이다. 파일 하나가 트랜잭션 하나다.
- 숫자·상태의 주인은 뷰로 둔다. 서버·화면은 뷰를 읽는다.
- 접속 주소는 `localhost`가 아니라 `127.0.0.1`로 쓴다(IPv6로 먼저 붙어 멈추는 일을 막는다).
- 행 단위 권한(RLS)을 쓰면:
  - 표마다 `ENABLE`과 `FORCE ROW LEVEL SECURITY`를 같이 건다(표 주인도 정책을 받게).
  - 정책은 경계 값(`current_setting('app.<키>')`)을 기본값 없이 읽어, 경계 없이 돈 쿼리가 오류가 나게 한다.
  - 앱 계정·경계 밖 계정·마이그레이션 계정을 나누고, 테스트도 앱 계정으로 접속한다. 관리자 계정은 RLS를 건너뛰므로 시험이 거짓으로 통과한다.

## 5. 테스트

- 테스트 DB는 마이그레이션을 끝낸 템플릿 DB 하나를 만들고, 테스트 작업마다 `CREATE DATABASE … TEMPLATE …`로 복제해 쓴다. 이름에 실행 id를 넣어 동시에 도는 세션끼리 겹치지 않게 한다. 연결 풀은 작업마다 작게 두고 끝나면 닫는다.
- 서버를 띄우는 테스트는 빈 포트(`PORT=0`)를 받는다. 고정 포트를 쓰지 않는다.
- 외부 서비스는 주소를 환경 변수 하나로 바꿀 수 있게 하고, 테스트는 가짜 서버 하나에 모은다.
- e2e(Playwright)는 핵심 사용자 흐름 몇 개만 둔다. 화면의 글자·값은 순수 규칙 단위 테스트가 맡는다.
- CI는 DB를 붙인 테스트까지 push마다 돌린다.

## 6. 스킬

| 때 | 스킬 |
|---|---|
| 화면을 만들거나 고칠 때 | `antislop`(핵심, 먼저) + `antislop-ui`, `antislop-human`, 다시 배치되는 화면이면 `antislop-layoutmobile` |
| 화면 문구·안내 글 | `antislop-copywriting` |
| 코드 주석 | `antislop-code` |
| 모듈 경계 검사를 깔 때 | `/setup-ts-deep-modules`(사람만) |

- antislop은 세션마다 "작업 중(during)에 적용할지, 다 만든 뒤(after) 점검할지"를 묻는다. 매번 묻지 않게 하려면 사람이 `npx antislop-ai --mode during`을 한 번 돌린다(이 컴퓨터 전체에 저장된다).
- antislop은 걸러 내기만 하고 디자인 방향을 정해 주지 않는다. 화면 작업 전에 `DESIGN.md`(색·글꼴·분위기)를 사람이 정해 둔다.
- `setup-ts-deep-modules`는 만든 사람이 아직 시험 중으로 분류했다. 층 순서 규칙은 빈칸으로 남겨 주므로 project.md의 층 순서로 채운다.
